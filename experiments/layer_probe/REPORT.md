# 策略自己的隐藏层当判官：分层线性探针

设想是让策略的"前半部分"兼任判官，和策略一起训练。这一步先问两件事：
- 基座策略自己的隐藏层里有多少对错信号？
- 用线性探针读出来的判官，会不会像 Kev-4B 一样为答案后的重复多给分？

这一步用了一次 Colab 运行（RTX PRO 6000），约 25 分钟。

**这是事后的探索性分析。** 层、读法、"写出答案"的对照和下面的检验，都是在这个项目的结果出来之后才定的，结论只能当作假设。

## 方法

- **模型和输入。** 模型是 Qwen3.5-4B-Base，即策略的基座，不加 LoRA。输入是 GRPO 的提示加上解答，解答按判官的方式截到 1536 个 token（`clip_solution`）。
- **读取的特征。** 取第 8/16/24/32 层之后的残差流，有两种读法：解答的最后一个 token（末 token），或解答各 token 的平均（平均）。
- **探针。** L2 正则的逻辑回归，标签是验证器的判决。在第二部分 judge study 的 4000 条基座解答上按题五折交叉拟合，所以每条解答都由没见过这道题的模型打分。正则强度由内层三折选出，最后都落在 0.1–0.3。
- **"+策略样本"变体。** 训练集里再加 2000 条策略自己的训练解答。它们来自 kev_only、rlvr_kev_gate、sub_kev、sub_kev_recal 的种子 2，第 100–199 步均匀抽样（`sample_rollouts.js`），约 9% 是"错且重复"。题目按 id 从 MATH 训练集取回，和 judge study 不重叠。作为检查，正确解答里 82% 的最终答案与数据集的答案逐字相同（验证器还接受等价写法），说明 id 对应的是同一道题。
- **重复测试。** 用的是第二部分重复探针（`dcjev/llm/repeat_probe.py`）的全部文本，在 Colab 上用同一段代码重建。重建结果与仓库里的重复探针一一对应：每种改动、每个来源、每种判决的条数都相同，每个 run 因截断改变答案而跳过的条数也相同。截断对共 2466 个，其中 432 个是错误解答。
  - end3 把最后两段在末尾再写两遍，twice 把整篇写两遍，都加在 judge study 的基座解答上。它们由没见过这道题的折模型打分。
  - 截断对来自六个 GRPO run 最终的 MATH-500 解答，由用全部数据拟合的模型打分。这些题也在 judge study 里，所以这个模型见过同一道题的基座解答。不过溢价是同一条解答剪与不剪之差，这点泄漏对两边相同。
- **参照。** 参照判官是 Kev-4B 和 AR 判官，用 judge study 与重复探针里已有的打分，和 `experiments/judge_combos` 相同。
- **对照与单位。** judge study 里 42% 的错误解答没有 `\boxed`，而正确解答全都有，所以排序另报"只看写出答案的"和"没答案的排最后"两种。重复溢价以该打分在写出答案的解答上的对错差距为单位。

## 结果

### 1. 排序：大胜来自认出没写答案的解答

题内 AUROC：

| 打分 | 全部解答 | 只看写出答案的 | 全部解答，没答案的排最后 |
|---|---|---|---|
| 第 8 层 末 token | 0.844 | 0.714 | 0.855 |
| 第 16 层 末 token | 0.884 | 0.784 | 0.892 |
| 第 16 层 平均 | 0.854 | 0.798 | 0.897 |
| 第 16 层 平均 +策略样本 | 0.866 | 0.810 | 0.905 |
| 第 24 层 末 token | 0.888 | 0.795 | 0.894 |
| 第 32 层 末 token | 0.865 | 0.759 | 0.873 |
| Kev-4B c | 0.819 | 0.822 | 0.912 |
| Kev-4B mean(c,g,q) | 0.834 | 0.829 | 0.916 |
| AR 判官 | 0.800 | 0.852 | 0.925 |

- **全部解答上的大胜。** 第 16 层和第 24 层的末 token 探针比 Kev-4B 的 c 高 0.064 [0.039, 0.081] 和 0.069 [0.046, 0.079]（按题自助法）。
- **大胜的来源是没写答案的解答。** 末 token 探针已经几乎把它们都排在最后：再加上"没答案排最后"，题内 AUROC 只涨约 0.01。平均探针涨 0.04–0.06，Kev-4B 的 c 涨约 0.09，AR 判官涨约 0.13。
- **只看写出答案的解答，探针落后。** 最好的探针是 0.81，Kev-4B 是 0.82，AR 判官是 0.85。
- **加上一条规则后的排名。** 给每个判官都加上"没答案就排最后"这条一行规则：AR 判官 0.925 > Kev-4B 0.912–0.916 > 最好的探针 0.905。
- **层的规律。** 第 16 层和第 24 层最好，两者相近；第 8 层最弱；末 token 到第 32 层回落。

### 2. 重复：读法决定盲区

单位是该打分在 judge study 写出答案的解答上的对错差距（`analysis.txt` 第 2b 节；第 2 节用的是全部解答上的差距）。

| 打分 | GRPO 答案后的尾巴：错 / 对 | 按来源（错） | 末尾再写两遍最后两段：对 |
|---|---|---|---|
| 末 token（4 层） | −0.11 至 0.07 / −0.25 至 −0.12 | −1.52 至 0.63 | −1.09 至 −0.06 |
| 平均（4 层） | 0.27 至 0.34 / 0.07 至 0.12 | 0.06 至 0.50 | −0.08 至 0.08 |
| Kev-4B c | 0.28 / 0.16 | 0.16 至 0.35 | 0.04 |
| AR 判官 | 0.03 / 0.05 | −0.14 至 0.10 | 0.07 |

- **末 token 探针平均不为尾巴多给分，但它并不忽略尾巴。**
  - 对正确解答，它还略扣分。
  - 按来源看摆动很大：从 sub_kev/s1 的扣 1.5 个差距，到 kev_only/s1 的加 0.6 个。
  - 在正确解答末尾把最后两段再写两遍，第 16 层扣 1.09 个差距，第 8 层扣 0.80。
  - 看起来它读的是"文本怎么结尾"。
- **平均探针对尾巴的溢价（0.27–0.34）和 Kev-4B 的 c（0.28）差不多。**
- **AR 判官仍是唯一对尾巴基本没反应的。**

### 3. 迁移到策略自己的解答

只用基座解答训练的探针，直接给 2000 条 GRPO 训练解答打分。下表是全体 AUROC，括号里是只看写出答案的：

| 打分 | AUROC |
|---|---|
| 平均（4 层） | 0.888–0.918（0.832–0.876） |
| 末 token（4 层） | 0.808–0.849（0.709–0.766） |
| Kev-4B c | 0.902（0.850） |

平均探针迁移得好，与 Kev-4B 相当；末 token 探针明显变差。

同一批样本上，只比写出答案的解答，重复的比不重复的得分高。错误解答上，末 token 探针高 0.31–0.45 个差距，平均探针高 0.25–0.35，Kev-4B 的 c 高 0.47；正确解答上分别是 0.01–0.17、0.24–0.32 和 0.22。这里的单位是这批样本自己写出答案部分的对错差距。这是观察性比较，两组解答的题目和内容都不同，不能只归因于尾巴；尾巴本身的因果效应以第 2 节的截断为准。

### 4. 加入策略自己的样本

- **排序几乎不变**：题内 AUROC 变化 −0.002 到 +0.012。
- **第 24/32 层的末 token 探针矫枉过正**：对尾巴改为明显扣分，错误解答 −0.27 和 −0.30，正确解答 −0.32 和 −0.35。
- **平均探针对尾巴的溢价基本不变**：0.21–0.33。

## 结论

- **信号在，但线性读出不够。** 策略中间层（第 16–24 层）的对错信号便宜好用：一个线性头就能认出没写答案的解答，在写出答案的解答上也有 0.78–0.81。要在真正的判断上超过现成判官，线性读出还不够，可能需要像 Kev-4B 那样训练 LoRA，或者在答案所在的位置读。
- **两种读法各有盲区。**
  - 末 token 探针对结尾的改动很敏感，迁移到策略的解答上也明显变差。
  - 平均探针迁移得好，却和 Kev-4B 一样为答案后的重复多给分。训练集里加进 2000 条策略样本（其中 175 条错且重复）后，这个溢价也只从 0.27–0.34 变成 0.21–0.33。
  - 相比之下，`experiments/judge_combos` 第 5 节里在线重拟合的头，在有标签约束的错误解答上已不再为重复多给分，在正确解答上仍多给一点。
  - 所以和策略一起训练的判官，很可能要持续在策略的新样本上用验证器的标签重拟合，并专门检查重复这类不改变答案的改动。
- **先要赢过的基线。** AR 判官加"没答案排最后"这条规则，排序最好（0.925），对重复也基本不多给分。
- **还没测的风险。** 真正共同训练时，策略梯度会改动判官所读的那些层。这里的探针读的是冻结的基座。

## 局限

- 只试了线性探针，每折只用 3200 条基座解答训练。标签里混着"写没写出答案"，探针学到的有相当一部分是这一点（第 1 节）。
- 一个基座模型，一套题（MATH-500 和 GSM8K 子集），一次划分。
- 策略样本只来自四个用 Kev-4B 训练的 run。

## 文件

```bash
# 本地（Node）：抽取策略样本（结果不提交，几秒钟）
node experiments/layer_probe/sample_rollouts.js
# GPU（kev 的环境，见 setup_light.sh 和 run_remote.sh）：
#   --data 指向一个目录，按仓库路径放 judge study 的 completions.jsonl.gz 和六个 run 的 final_completions.jsonl.gz，
#   再放 rollout_sample.jsonl.gz；--math 是 dcjev.llm.data 生成的 math_train.jsonl
python experiments/layer_probe/probe.py extract --data <dir> --math <math_train.jsonl> --out <out>
python experiments/layer_probe/probe.py fit --out <out>
# 本地（Node）：本文的数字
node experiments/layer_probe/analyze.js
```

- `probe.py`：特征提取和探针拟合，在 Colab 上运行；提取 1.89 万条文本、1350 万 token 用 9.4 分钟，拟合约 2.5 分钟。
- `setup_light.sh`、`run_remote.sh`：这次在 Colab 上用的环境安装和运行脚本，路径是 Colab 上的。
- `sample_rollouts.js`：抽取策略样本，生成 `in/rollout_sample.jsonl.gz`（没有提交）。
- `analyze.js`：读取探针打分，与 Kev-4B、AR 判官比较。
- `results/scores.jsonl.gz`：每条文本、每个探针的 P(对)。
- `results/fit.json`、`results/extract.json`、`results/*.log`：拟合与提取的记录。
- `results/analysis.json`、`results/analysis.txt`：本文全部数字，第 2 节的表在 `analysis.txt` 的 2b。特征本身约 1.5 GB，没有保存。
