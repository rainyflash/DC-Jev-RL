# 草稿切换的逐步分析（方向 1 第①步）

这份笔记只用仓库里已有的训练解答，逐步分析六个 run 怎样改成先写草稿，没有用 GPU。数据是 26 个 GRPO run，每个 run 200 步，每步 16 道题 × 8 条解答，共 25,600 条。

**这是事后的探索性分析。** 草稿的定义沿用论文（`dcjev/analysis/part2.py` 的 `informal_opening`：前 300 个字符里没有 `$`、`\(`、`\[`、`###` 或 `**`），而这个定义是读过解答之后才定的。下面的检验也是看过数据之后设计的，所以结论只能当作假设，不能当作验证。

## 方法

- **复现论文口径。** `analyze.js` 读取每个 run 的 `rollouts.jsonl.gz`、`log.jsonl.gz` 和 `final_completions.jsonl.gz`。它先重算论文每 50 步一个窗口的草稿占比和组内对错差，再与 `experiments/*/results/summary.json` 里存档的值逐一比较。26 个 run 全部一致（最大差 3e-16）；只要有一处不一致，脚本就停止。
- **选择差 S。** 在一步之内，计算"是否草稿"与优势在组内的协方差，只用参与更新的解答。按一阶近似，S > 0 时一次策略梯度更新会提高草稿的概率。零假设是组内随机打乱草稿标签；这时 S 的标准差可以解析算出。
- **同种子配对。** 同一种子的 run 每一步看到的题目相同、顺序也相同（扁平采样时连采样种子也相同），所以可以在相同的题目上逐题比较准确率。
- **汇总。** `summarize.js` 生成下文的数字，并写入 `results/summary.json`。

## 结果

### 1. 草稿占比先降后升，升得很快，还可能反复

所有 run 开始时（温度 1 采样）都有 11–18% 的解答以草稿开头。前 50–90 步里，草稿比其他解答更常答错，占比降到几个百分点。

- **未切换的 20 个 run：** 此后一直很低，第 100 步之后任何 10 步窗口的占比至多 8.3%。
- **切换的 6 个 run：** 从低谷反弹，见下表（按 5 步滑动平均）。

| run | 低谷 | 到 20% | 到 50% | 20%→50% 用时 |
|---|---|---|---|---|
| rlvr_kev_add/s3 | 1%（第 108 步） | 第 156 步 | 第 162 步 | 6 步 |
| rlvr_kev_gate/s2 | 2%（第 59 步） | 第 133 步 | 第 139 步 | 6 步 |
| sub_probe/s1 | 10%（第 31 步） | 第 50 步 | 第 75 步 | 25 步 |
| sub_probe/s2 | 0%（第 79 步） | 第 108 步 | 第 116 步 | 8 步 |
| tree_kev/s1 | 3%（第 149 步） | 第 179 步 | 第 197 步 | 18 步 |
| tree_random/s2 | 0%（第 78 步） | 第 122 步 | 第 131 步 | 9 步 |

切换也可能反复：rlvr_kev_gate/s2 在第 150–169 步从 78% 退回 18%，之后又升到 85%。

### 2. 上升不是因为草稿拿到了更多奖励

- **组内对错持平。** 在每个 run 到达 50% 之前的 20 步里，六个 run 合计，草稿与同组其他解答的对错差为 0.0 个百分点 [−1.4, 1.8]（767 个组，按组自助法）。选择差合计 z = 0.8。
- **选择差远不够解释上升速度。** 用前 50 步粗略标定：累计选择差每增加 1，草稿占比的 logit 大约变化 1（斜率 1.0，r = 0.30）。上升期每 10 步 logit 实际增加 0.8–1.9，而按当时的选择差应为 −0.1 到 −0.4。
- **风格变化与奖励偏好方向相反。** LaTeX 标记更密的解答拿到更多优势：这一项的选择差在六个 run 的上升期都为正。可是切换时，连非草稿解答的 LaTeX 密度也大幅下降，例如 rlvr_kev_add/s3 从每千字符 47 个标记降到 20 个。
- **奖励偏向草稿时，占比反而下跌。** rlvr_kev_gate/s2 回落期间（第 150–169 步），草稿比同组其他解答更常答对（+3.9 个百分点 [−0.6, 8.6]，选择差 z = 1.4），占比却从 78% 掉到 18%。

### 3. 切换是全局的

在到达 20% 的那个 25 步窗口里，七个科目的草稿占比同时上升。例如 rlvr_kev_add/s3 的各科占比从 1–17% 升到 33–69%；计数与概率的占比最高，中级代数最低。

按难度看也一样。这里用同种子未切换 run 在同一步、同一道题上的准确率给题目分成四档，这样难度不受切换 run 自己的草稿影响。各档的草稿占比同时上升，幅度相近，例如 rlvr_kev_gate/s2 各档都从 3–4% 升到 48–51%。

### 4. 前 100 步看不出哪些 run 会切换

- **第 0–49 步：** 我检验了 11 个指标，即草稿占比、选择差、组内对错差、非草稿的 LaTeX 密度、前 100 字符无标记的比例、训练准确率、截断率、长度、全对组比例、梯度范数和优势尺度。没有一个能把六个 run 和其他 20 个区分开（精确置换检验 p ≥ 0.09）。
- **第 50–99 步：** 切换的 run 训练准确率略高（63.5% 对 62.3%，p = 0.03），与第 6 节里切换前已有的小幅领先一致。草稿占比也更高，但主要来自已经开始上升的 sub_probe/s1。一共检验了 22 次，单凭这些不足以预测哪些 run 会切换。

### 5. 占上风的写法基座里就有，之后变得更省字

- **基座里已有：** 第 0–24 步，所有 run 的草稿中最常见的开头是 "We need to…"（12%）和 "We are given…"（10%）。第 175–199 步，切换了的 run 里 "We need to…" 占 36%。
- **之后更省字：** 切换后，六个 run 中有四个出现了省掉冠词或 "to" 的写法（"We need probability that…"、"We need count of…"）。这种写法在切换 run 的最终 MATH-500 解答中占 6–55%，在其他 20 个 run 的任何 25 步窗口里至多 0.31%。

### 6. 切换与准确率跃升同时发生

- **贪心 MATH-500：**
  - 在包含 50% 切换点的那个 50 步评测区间里，切换的 run 平均提高 4.5 个百分点（1.8–7.2）。同种子未切换的 run 在同一区间平均 +0.1；重复评测的噪声标准差是 0.8。
  - 未切换 run（不含 kev_only）在第 50 步之后有 54 个评测区间，只有 4% 提高了 ≥3 个百分点（最多 4.0）；切换区间则是 6 个中有 5 个。
- **相同训练题目上：** 切换 run 相对同种子未切换 run 的领先（95% 区间大约 ±1.5 个百分点）：
  - 上升前 40 步：已经是 +0.1 到 +1.9（5 个中有 4 个的区间不含 0）；
  - 上升期间：+0.9 到 +3.3；
  - 上升后 40 步：+3.5 到 +4.7。
  - tree_kev/s1 切换得太晚，没有"之后"，不计入。

### 7. 但准确率不取决于开头

- **同一策略、同一道题的两种开头：** 在最终策略里比较同一道题的草稿解答和非草稿解答（AIME24、AIME25、AMC23，每题 16 个样本）。开头由策略自己采样决定，所以这比较的是同一策略在同一道题上走草稿路径和走正式路径的差别。
  - 切换了的 run：草稿比非草稿 +0.9 个百分点 [−4.1, 6.2]（60 道题，大多来自两个树状 run）。
  - 其他 run：+2.5 [−1.7, 6.7]（159 道题）。
  - 作为对照，切换了的 run 在这些集合上整体领先 10.8 个百分点（42.0% 对 31.2%）。
- **风格退回，领先保留：** rlvr_kev_gate/s2 的草稿占比从 77% 退到 13% 时，它在相同题目上的领先没有缩小，反而从 2.1 扩大到 4.4–6.7 个百分点。

## 结论（假设）

草稿开头更像是这些 run 中某种全局变化的可见标志，而不是准确率的来源。理由有三：
- 它的扩散不是由奖励驱动的；
- 在同一策略内，开头不改变准确率；
- 风格退回时，准确率的领先可以保留。

这个全局变化本身是什么，日志里看不出来。

## 对后续的影响

- **第②步（强制开头）：** 同一策略内的自然对照已经提示，给未切换的策略强制草稿开头，大概带不来接近 10 个百分点的提升。它仍值得做，但只能算一次便宜的确认。
- **更有信息量的问题：** 这种跃升是不是随机事件，只要训练够久，多数种子都会发生？六个 run 的起点从第 50 步到第 180 步分布得很散，更像一个随时可能发生的事件。检验方法：用 HF 上未切换的适配器（rlvr_sub/s2、tree_kev/s3、tree_random/s3），各用几个种子再训练 200 步。这需要 Colab。
- **不需要 GPU 的下一步：** 在切换前后两次周期评测（`evals/step*.jsonl.gz`）里，找出同一批 MATH-500 题目中从错变对的解答，比较推理内容变了什么。开头风格在同一时间也变了，比较时要把它分开。
- **方法上：** 同种子配对（相同题目、相同顺序）能把 run 之间的准确率差估到 ±1.5 个百分点左右。比较 RLVR 变体时值得采用。

## 局限

- **事后分析：** 只有六个切换的 run，草稿定义和这些检验都是看过数据之后定的。
- **标定很粗：** 从选择差到 logit 变化的标定会受 Adam 优化器、LoRA 和噪声造成的斜率偏低影响。不过上升期的选择差本身接近零，这一点不依赖标定。
- **同策略对照样本少：** 同一策略内的比较依赖策略自己偶尔采样出的另一种开头。切换了的扁平 run 几乎没有非草稿样本，所以这部分主要来自两个树状 run。
- **评测间隔粗：** 周期评测每 50 步一次，无法定位跃升的确切步数。

## 文件

在仓库根目录用 Node 运行，不需要 Python 或 GPU：

```bash
node experiments/draft_switch/analyze.js
node experiments/draft_switch/summarize.js
```

- `analyze.js`：读取 run 并逐步计算，先校验与论文存档一致。
- `summarize.js`：生成本文的数字。
- `results/summary.json`：本文全部数字。
- `results/per_step.csv`：每个 run 每一步的统计，共 5,200 行。
- `results/validation.json`：与论文存档的比较。
- `results/runs.json`：完整的逐步、逐窗口和逐题数据，由 `analyze.js` 生成；约 9 MB，没有提交。
